from django.urls.resolvers import URLPattern, URLResolver

def names(patterns, prefix=''):
    found = set()
    for item in patterns:
        if isinstance(item, URLResolver):
            child_prefix = prefix
            if item.namespace:
                child_prefix += item.namespace + ':'
            found |= names(item.url_patterns, child_prefix)

## Project audit — confirmed findings

I checked the Django app, its URL routes and templates, the separate `UI` mockups, and the test suite. Here are the concrete issues I could confirm in this pass.

### High priority

1. **Vercel deployment is likely blocked.**  
   `vercel.json` specifies Python 3.9, while the project uses Django 6 and documents Python 3.12+. It also references `build_files.sh`, which is missing from the project. Align the runtime and either add the build script or remove that build entry.

2. **The documented fresh local setup does not match the database settings.**  
   The `README` says SQLite is the local default and that `DATABASE_URL` is optional. But `settings.py` configures PostgreSQL and requires `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, and `DB_PORT`; the documented `DATABASE_URL` is not used there. A fresh setup following the README can fail before migrations. Make the settings and instructions agree.

3. **Production can fall back to a known development secret key.**  
   `settings.py` supplies a fixed insecure fallback if `SECRET_KEY` is absent. Require a real environment-provided key for deployment rather than silently using that fallback.

4. **A local notes file contains plaintext credentials.**  
   `notes.txt` contains credentials, which I have not repeated here. Keep it out of submissions and shared copies; rotate any credentials that are still valid.

### UI and feature gaps

5. **Several links visible in the live app do nothing.**  
   The mobile navigation’s Home, Visits, Rx, Billing, and Profile links all point to `#` in `bottom_nav.html`, and that navigation is included by `base.html`. The doctor’s Prescriptions link and the admin Reports & Analytics link are also placeholders in `navbar.html` and `navbar.html`. The login page’s Forgot password, Privacy Policy, and Terms links are placeholders too in `login.html`.

6. **Some screens in `UI` are mockups, not wired app pages.**  
   The separate `UI folder` contains standalone HTML designs, but the Django app serves templates from `shms/templates` through its URL configuration. Treat items such as analytics, settings, and standalone medical-history screens in those mockups as unimplemented unless you connect them to Django views and routes. The payment gateway is also not implemented; the README describes payment recording as internal rather than an online gateway.

### Bugs and test results

7. **Past-appointment counts can disagree with the displayed list.**  
   In `appointments/views.py`, `past_count` counts only completed or cancelled appointments. But `appointments/models.py` classifies any appointment that is not upcoming as “past.” An overdue appointment still marked scheduled or confirmed can therefore appear under Past Visits without being included in its counter. Base the counter on the same classification used for the cards.

8. **One test fails because its expected result conflicts with the account scope.**  
   `manage.py test` ran 46 tests: **45 passed, 1 failed**. `test_admin_cannot_toggle_own_account` expects a redirect, but `toggle_account_status` only looks up managed non-admin accounts, so targeting the admin returns 404. Decide the intended behavior and make the test and endpoint agree; the current behavior is consistent with excluding admin accounts from that management list.

### Checks that passed

- `manage.py check`: no issues reported.
- Migration check: no model changes pending.
- All Django templates parsed, and all named `{% url %}` references resolved; I found no broken named Django routes.

I did not make changes. The first fixes I’d prioritize are the deployment configuration, the database setup mismatch, and the visible placeholder navigation.
